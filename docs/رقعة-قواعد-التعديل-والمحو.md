# رقعةُ قواعد الأمان — التعديلُ المحكوم والمحوُ النهائيّ

> **القرارُ للمالك وحده.** الوكلاء يعدّلون `firestore.rules` في المستودع، و**المالكُ وحده ينشرها من Firebase Console** (دستور AGENTS.md).
> وهذه الورقةُ **لم تُطبَّق على `firestore.rules`** — هي نصُّ الرقعة وحجّتُها، لتُقرأ ثمّ تُقرَّر.
>
> **التاريخ:** 2026-10-02 · **السبب:** طلبُ المالك «خاصية التعديل في كل مرحلة مستند» و«خاصية حذف مستند».

---

## ١. ماذا يعمل اليوم بلا أيّ نشر

| الطلب | الحالة اليوم | من يملكه الآن |
|---|---|---|
| تعديلُ مسودّة | ✅ يعمل | صاحبُها · المدير العامّ |
| تعديلُ مستندٍ **مُرسَلٍ أو معتمَد** | ✅ يعمل | **المدير العامّ وحده** (`isAdmin()` في `allow update`) |
| تعديلُ منجَزٍ/مغلقٍ/ملغى | ⛔ ممنوعٌ بقرارٍ دائم | لا أحد — والتصحيحُ بمستندٍ عكسيّ |
| «حذفُ» مستند = **إلغاؤه** (`canceled`) | ✅ يعمل | صاحبُ المسودّة · المعتمِد على المعتمَد |
| **محوٌ** نهائيٌّ من قاعدة البيانات | ⛔ مستحيل | لا أحد — `allow delete: if false` |

**فالطلبُ ١ و٢ و٣ منفَّذٌ وعاملٌ الآن للمدير العامّ، ولكلّ الأدوار على المسودّات.** وما تحتاجه الرقعةُ أمران فقط: توسيعُ التعديلِ المحكومِ إلى **مدير المستودع**، وإتاحةُ محوِ المسودّة التي **لم تُرقَّم قطّ**.

وحتى تُنشَر، تقول الواجهةُ الحقيقةَ ولا تَعِد: `amendVerdict().serverReady` تُعيد `false` لمدير المستودع، و`removalOptions()` **لا ترسم زرَّ المحو أصلًا** وتكتب سببَ غيابه. فلا زرَّ يُضغَط ثمّ يرتدّ من الخادم.

## ٢. الرقعةُ الأولى — التعديلُ المحكومُ لمدير المستودع

### الموضع
`firestore.rules` · داخل `match /documents/{docId}` · في قائمةِ بوّابات `allow update`.

### ما يُضاف

```
      // ── التعديلُ المحكوم (طلبُ المالك 2026-10-02 · م١ من رقعة التعديل) ──
      //
      // ★★★ القاعدةُ المجاورة `contentUnchanged()` تمنع المعتمِدَ من تبديل
      //    البنود **في نفس كتابة الاعتماد** — وذلك المنعُ يبقى كما هو ولا
      //    يُمسّ. والممنوعُ هناك هو التبديلُ **المستخفي داخل كتابةِ حالة**.
      //
      //    وهذه بوّابةٌ أخرى تمامًا: كتابةٌ **لا تمسّ الحالةَ** (فلا تعتمد ولا
      //    تُنهي)، ويُشترط فيها وسمُ `amended` باسم كاتبه وبختم الخادم. أي
      //    أنّ التعديلَ يصير **فعلًا معلَنًا موقَّعًا** لا تبديلًا صامتًا.
      //
      // ⚠️ ولا تُتاح على `done` ولا على مُقيَّد: المنجَزُ رحّل حركاتٍ في دفترٍ
      //    ملحق-فقط، فتعديلُ بنوده يترك حركةً لا يبرّرها مستند.
      //
      // ⚠️ ازدواجٌ مقصودٌ مُعلَن: قائمةُ الأدوار هنا تكرّر `AMEND_ROLES` في
      //    `src/services/documents/amendGuard.js`. القواعدُ لا تستورد JS.
      //    **عدّلهما معًا** — و`amendGuard.test.js` يحرس ذِكرَ الدور هنا.
      function isGovernedAmend() {
        return hasProfile()
               && myRole() in ['warehouse_manager']
               && resource.data.state in ['submitted', 'approved']
               // الحالةُ لا تتغيّر: هذه كتابةُ تصحيحٍ لا كتابةُ نقلة.
               && request.resource.data.state == resource.data.state
               // ولا تمسّ مستندًا مُقيَّدًا في الدفتر.
               && resource.data.posted != true
               // الحقولُ المسموحةُ معدودة — لا كائنٌ كامل. و`posted` خارجَها
               // فلا يُقيَّد مستندٌ من باب التعديل.
               && request.resource.data.diff(resource.data).affectedKeys()
                    .hasOnly(['header', 'lines', 'amended', 'updatedAt'])
               // والوسمُ صادقٌ: ختمُ الخادم، وكاتبُه هو الفاعل، وبسببٍ مكتوب.
               && request.resource.data.amended.at == request.time
               && request.resource.data.amended.byUid == request.auth.uid
               && request.resource.data.amended.reason is string
               && request.resource.data.amended.reason.size() > 0;
      }
```

ثمّ يُضاف `|| isGovernedAmend()` إلى قائمةِ بوّابات `allow update` — **بعد** `isSideEffectStamp()` وقبل بوّابات النقلات.

### لماذا هذه الصيغةُ آمنة

| الخطر | ما يمنعه |
|---|---|
| المعتمِدُ يبدّل السعرَ ثمّ يعتمد في كتابةٍ واحدة | `request.resource.data.state == resource.data.state` — الكتابةُ لا تنقل حالةً، فلا تجتمع مع اعتماد |
| تعديلٌ بلا أثر | `amended.reason` إلزاميّةٌ غيرُ فارغة، و`amended.at == request.time` فلا تُؤرَّخ من المتصفّح |
| نسبةُ التعديل إلى غير فاعله | `amended.byUid == request.auth.uid` |
| تعديلُ ما قُيِّد في الدفتر | `resource.data.posted != true` |
| تقييدُ مستندٍ من باب التعديل | `posted` خارج `hasOnly` |
| تزويرُ الرقم أو الهويّة | `immutableKept()` و`numberWriteOnce()` قائمتان على كلّ تحديث |
| كلُّ معتمِدٍ يصير مُعدِّلًا | القائمةُ `['warehouse_manager']` وحدَها — لا `approveRoles(type)` |

**ولا يُستعمل `approveRoles(docType)` هنا بحالٍ**: لو فُعل لعاد بابُ «المالي يبدّل سعرَ أمر الشراء» مفتوحًا بخطوتين بدل خطوة. ومديرُ المستودع سلطةٌ تشغيليّةٌ **خارج سلسلة الاعتماد الماليّ**.

## ٣. الرقعةُ الثانية — محوُ المسودّة التي لم تُرقَّم

### الحجّة

القاعدةُ الحاليّة `allow delete: if false` وتعليقُها «لا حذف لمستند أبدًا. المستند الخاطئ يُرفض ويبقى أثره» — **صحيحةٌ تمامًا للمستند المرقَّم**: الرقمُ الرسميُّ موضعٌ في تسلسلٍ قانونيّ، وثغرةٌ في التسلسل أوّلُ ما يسأل عنه مدقّقٌ خارجيّ.

لكنّ المسودّةَ التي **لم تُرقَّم قطّ** (`number == null`) ليست في أيّ تسلسل: لا رقمَ يُثقَب، ولا حركةَ في الدفتر، ولا سلسلةَ تشتقّ منها (`canDeriveFrom` تمنع الاشتقاق من المسودّة). فهي أقلُّ شيءٍ في هذا النظام يستحقّ أثرًا دائمًا — وبقاؤها يُراكم ركامًا في «مستنداتي» لا معنى له.

### ما يُستبدل

```
      // لا حذف لمستند أبدًا. المستند الخاطئ يُرفض ويبقى أثره.
      allow delete: if false;
```

بـ:

```
      // ── المحوُ: للمسودّة التي لم تُرقَّم قطّ وحدَها (م٢ من رقعة التعديل) ──
      //
      // القاعدةُ الأمُّ باقيةٌ بحرفها: **المستندُ المرقَّم لا يُمحى أبدًا** —
      // رقمُه موضعٌ في تسلسلٍ قانونيّ، وثغرةُ التسلسل أوّلُ ما يُسأل عنها.
      // والخاطئُ المرقَّمُ يُلغى (`canceled`) فيخرج من كلّ قائمةٍ ويبقى أثرُه.
      //
      // وهذا الاستثناءُ لما لا أثرَ له أصلًا: مسودّةٌ بلا رقمٍ ولا قيدٍ ولا
      // مشتقّاتٍ (و`canDeriveFrom` تمنع الاشتقاق من المسودّة أصلًا).
      allow delete: if signedIn()
                    && resource.data.number == null
                    && resource.data.state in ['draft', 'rejected']
                    && resource.data.posted != true
                    && (resource.data.createdByUid == request.auth.uid || isAdmin());
```

### وما يبقى ممنوعًا بعد النشر

- محوُ أيّ مستندٍ **رُقِّم** — ولو كان ملغًى، ولو طلبه المدير العامّ.
- محوُ أيّ مستندٍ قُيِّد (`posted == true`).
- محوُ مستندٍ في `submitted`/`approved`/`done`/`closed`/`canceled`.
- محوُ مسودّةِ غيرك إن لم تكن مديرًا عامًّا.
- محوُ سجلّ التدقيق أو المرفقات أو المطابقة — `allow update, delete: if false` عليها **لم تُمسّ**.

> ⚠️ **ملاحظةٌ صريحة:** محوُ مستندٍ في Firestore **لا يمحو مجموعاتَه الفرعيّة**: يبقى قيدُ التدقيق **يتيمًا** غيرَ مقروءٍ من الواجهة. ولهذا بقي المحوُ محصورًا بما لا أثرَ له يُطلَب أصلًا. ومن أراد نظافةً تامّةً فالإلغاءُ (`canceled`) هو الطريق — يُخرج المستندَ من كلّ قائمةٍ ويُبقي سجلَّه متّصلًا.

## ٤. كيف تُنشَر

1. افتح `firestore.rules` في المستودع وطبّق ما فوق (أو اطلب من الوكيل تطبيقَه — يُطبَّق في المستودع ولا يُنشَر).
2. Firebase Console → Firestore Database → Rules → الصق → **Publish**.
3. بعد النشر: اضبط العلامةَ التي تقرؤها الواجهة (`rulesPublished`) إلى `true` — أو أبلِغ الوكيلَ ليربطها بإعدادٍ في `settings`، فتظهرَ أزرارُ المحو تلقائيًّا.

## ٥. وكيف تُجرَّب بعد النشر

| الاختبار | المتوقَّع |
|---|---|
| مديرُ مستودعٍ يعدّل بنودَ استلامٍ **معتمَد** بسببٍ مكتوب | ✅ يُقبل · ويظهر قيدُ `amend` بالقيمتين قبل/بعد |
| المديرُ نفسُه يعدّل بلا سبب | ⛔ يرتدّ من الخادم |
| مفتّشُ جودةٍ يعدّل بنودَ ما يعتمده | ⛔ يرتدّ (ليس في القائمة) |
| مديرُ مستودعٍ يعتمد **ويعدّل** في كتابةٍ واحدة | ⛔ يرتدّ (`state` تغيّرت) |
| تعديلُ مستندٍ **منجَز** | ⛔ يرتدّ (`state` ليست في القائمة) |
| محوُ مسودّةٍ بلا رقم من صاحبها | ✅ يُقبل |
| محوُ مستندٍ مرقَّمٍ ملغًى من المدير العامّ | ⛔ يرتدّ |

وهذه الصفوفُ السبعةُ هي ما يُكتب في `test/firestore-rules.test.mjs` (يحتاج مُحاكي Firestore: `npm run test:rules`).
