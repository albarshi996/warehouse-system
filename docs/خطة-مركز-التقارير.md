# القسم ١ — الفهم المؤكَّد

طلبتَ **طبقة تقارير** تغطّي كلّ ما في البوابة، ولكلّ تقرير **ثلاث قدرات إلزاميّة**:

| القدرة | المعنى |
|---|---|
| **فلترة** | مدّة · مستودع · قطاع · فرع · صنف · فئة · شريك · دور · حالة · مستند |
| **طباعة** | A4 بهوية Brandzo والتوقيعَين المعتمدَين ورقمٍ إشاريّ |
| **تصدير إكسل** | ملفٌّ حقيقيّ `.xlsx` بأعمدةٍ قابلة للفرز، لا نسخًا من الشاشة |

والمجالات التي سمّيتَها:

1. **المخزون** — البحث عن صنفٍ فيُعرض تاريخه كاملًا: شراء · استلام · صرف · بيع · إتلاف · عجوزات.
2. **الموردون** — أرصدة **دائنة**: المدفوع · المتبقّي · التصفير.
3. **العملاء** — أرصدة **مدينة**: المحصّل · المتبقّي · التصفير.
4. **النقل** — حسب القطاعات.
5. **الجرد**.
6. **اللوجستيات واللوحات كاملةً**.
7. **وتقريرٌ لكلّ شاشةٍ ومستندٍ في القائمة التي أرسلتَها** — لا يُنسى شيء.

**فهمتُ أنّ الهدف:** ألّا يبقى في البوابة رقمٌ لا يُمكن استخراجه وطباعته وتحليله خارجها.

# القسم ٢ — اكتشافٌ حاكم يجب إقراره قبل البدء

## ٢‑أ · الحسابات (دائن/مدين) ليست تقريرًا — بل نظامٌ ناقص

فحصتُ الكود، والنتيجة صريحة:

| ما يلزم | الحالة اليوم |
|---|---|
| رصيد المورّد الحيّ | ❌ `accountBalance` **لقطةٌ افتتاحيّة مستوردة من إكسل**، لا تتحرّك مع أيّ مستند |
| رصيد العميل الحيّ | ❌ المثل |
| **سند قبضٍ من العميل** | ❌ **غير موجود إطلاقًا** — الفاتورة تُصدَر ولا شيء يسجّل التحصيل |
| سند سدادٍ للمورّد | ⚠️ `PV` موجود لكنّه يخدم **المشتريات الداخلية وحدها** لا سداد أوامر الشراء |
| دفتر ذمم يُقاصّ | ❌ غير موجود · ولا قيود مزدوجة (قرار سابق للمالك) |

**النتيجة:** «المدفوع · المتبقّي · التصفير» **لا يمكن حسابه من بياناتٍ غير موجودة**.
وأيّ تقريرٍ أبنيه اليوم سيعرض **الرصيد الافتتاحيّ المستورد جامدًا** — وهو أسوأ من
لا شيء، لأنّه يبدو صحيحًا وهو ميّت.

## ٢‑ب · القرار المطلوب منك

| الخيار | ما يعنيه |
|---|---|
| **أ (موصى به)** | نبني **وحدة الذمم** أوّلًا (المرحلة ر‑٢): سند قبض `RCP` + سند سداد `SPV` + دفتر ذمم ملحق-فقط + كشوف الحساب. **حينها تعمل الأرصدة حقًّا.** |
| ب | نبني بقيّة التقارير الآن، ونؤجّل الحسابات — فتبقى أرصدة الشركاء افتتاحيّة معطّلة. |
| ج | نعرض «المستحقّ» من الفواتير فقط بلا مدفوعات — نصف الحقيقة، ولا أنصح به. |

> ⚠️ هذا ليس اعتراضًا على طلبك، بل إبلاغٌ بأنّ بندًا منه يحتاج بناءً قبل التقرير.
> **قل «أ» فأبني الوحدة كاملةً.**

# القسم ٣ — بنية الحلّ: محرّك واحد لا ٣٣ شاشة

**الخطأ الذي سنتجنّبه:** بناء ٣٣ صفحةً كلٌّ بفلاترها وطباعتها وتصديرها. النتيجة
٣٣ نسخةً تتباعد، وتغييرٌ في الهوية يعني ٣٣ تعديلًا.

**البديل:** **محرّك تقارير واحد** يقرأ **تعريفًا** لكلّ تقرير:

```
{
  id, titleAr, docRefPrefix,          // BFP-SCM-RPT-…
  filters: [ …حقول الفلترة… ],
  columns: [ {key, label, type, width, align, total?} ],
  source:  (data, filters) => rows,   // دالّة خالصة تُختبَر في Node
  summary: (rows) => [ …بطاقات… ],
  print:   { orientation, groupBy?, signatures }
}
```

فإضافة تقريرٍ جديد = **ملفّ تعريفٍ واحد**، لا شاشة. والفلترة والطباعة والتصدير
تُبنى **مرّةً واحدة** وتخدم الجميع — كما فعل `SCHEMAS` مع المستندات الـ٣٥.

**ثلاث لبنات تُبنى مرّة:**

| اللبنة | الوصف |
|---|---|
| `reportEngine.js` | المحرّك: يُطبّق الفلاتر · يحسب المجاميع · يبني الملخّص. **خالص ومختبَر** |
| `reportPrint.js` | الطباعة: A4 بهوية Brandzo + الترويسة + التوقيعَان + الرقم الإشاريّ + ترقيم الصفحات |
| `reportExcel.js` | التصدير: `.xlsx` حقيقيّ بأعمدةٍ وأنواعٍ صحيحة (رقم رقمًا وتاريخ تاريخًا) |

وشاشةٌ واحدة `/dashboard/reports-center` تعرض الفهرس، وكلّ تقريرٍ يفتح فيها
بنفس الإطار.

# القسم ٦ — معايير القبول (لكلّ تقرير)

1. **الفلاتر تعمل مجتمعةً** لا منفردةً فقط.
2. **المجاميع تطابق** مجموع الصفوف المعروضة بعد الفلترة.
3. **الطباعة** بالهوية والتوقيعَين والرقم الإشاريّ وترقيم الصفحات، والجدول لا ينقطع.
4. **الإكسل** بأعمدةٍ حقيقيّة: الرقم رقمًا والتاريخ تاريخًا (لا نصًّا).
5. **الصفر ليس فراغًا:** التقرير بلا بيانات يقول «لا بيانات في هذا النطاق» لا يُعرض فارغًا.
6. **الصلاحيات:** كلّ تقريرٍ محصورٌ بأصحابه — كشف حساب العميل ليس للمندوب.
7. **الأداء:** ٥٠٠٠ صفٍّ بلا تجميد الشاشة.
8. **منطق كلّ تقريرٍ خالصٌ ومختبَر** في Node — لا حساب داخل المكوّن.
