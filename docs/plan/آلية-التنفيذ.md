## ١ — المشكلة التي تعالجها هذه الآليّة

ثلاثة أبواب يضيع منها العمل، وكلّها كانت مفتوحة قبل هذا المستند:

| الباب | الحال قبل | الحال بعد |
|---|---|---|
| **الخطة خارج المستودع** | الملفّ الوحيد على سطح مكتب المالك؛ عطبُ قرصٍ يمحو ١٨ جلسة تخطيط | الأصل في `docs/` بتاريخ git، وما على سطح المكتب مرآة |
| **الإنجاز في ذاكرة المحادثة** | الجلسة تمتلئ فيضيع «أين توقّفنا»، وتبدأ الجلسة التالية بالتخمين | حالة كلّ مهمّة في `phase-one.json`، وبطاقة استئناف صفحةً واحدة |
| **ملفّ التسليم تضخّم** | `SESSION_HANDOFF.md` تجاوز ٣٠٠ ك.ب — قراءته وحدها تستهلك الجلسة | البطاقة تُقرأ أوّلًا، والتسليم للسرد التاريخيّ لا للاستئناف |

**القاعدة الحاكمة:** ما ليس في المستودع فهو ضائع؛ وما ليس في المتتبّع فهو غير منجَز.

## ٣ — طقس الجلسة

### في أوّلها — أمرٌ واحد

```bash
npm run plan
```

يطبع: أين توقّفنا · ما الجاهز بلا انتظار أحد · ما المحجوب وبماذا · ما على المالك.
ثمّ اقرأ [`الاستئناف.md`](الاستئناف.md). **لا تقرأ `SESSION_HANDOFF.md` كلّه** — ٣٠٠ ك.ب تلتهم ثلث الجلسة.

### أثناءها

- **مهمّة واحدة `doing`** — الحارس يرفض جبهتين.
- كلّما أُنجز جزء، حدّث `progress` و`nextStep` في المهمّة. هذان الحقلان هما ما ينقذك إن امتلأت الجلسة **في منتصف** مهمّة لا بين مهمّتين.
- `nextStep` تُكتب **حرفيًّا قابلةً للتنفيذ**: «أضف `toBase` في `uomModel.js` وشغّل الاختبار العشرين» — لا «أكمل الوحدات».

### قبل إغلاق أيّ مهمّة

```bash
npm run build && npm test && npm run audit && npm run plan
```

ثمّ في `phase-one.json`: `state: "done"` + `evidence.commit` (اختصار الكوميت) + `guardTest` موجود فعلًا على القرص.
**الحارس يرفض `done` بلا كوميت وبلا اختبار حارس.** الإنجاز يُثبَت ولا يُدَّعى.

### في آخرها

سطر واحد في `SESSION_HANDOFF.md` بمعرّف المهمّة، وكوميت يبدأ بالمعرّف:

```
م١-ب: إخراج حقول المال من مخططات أودو
```

فيصير `git log --grep=م١-ب` كاشفًا لتاريخ كلّ مهمّة.

## ٤ — القواعد التي تمنع أن يصير عملنا سببًا في فساد

هذا هو جوهر الآليّة. النظام يعمل اليوم على بياناتٍ حقيقيّة، والمرحلة ٣ وحدها تمسّ **كلّ كميّة وكلّ سعر**. تغييرٌ واحد بلا احتياط يصنع حلقة: خطأ ← إصلاح متسرّع ← خطأ أعمق.

| # | القاعدة | كيف تُحرَس |
|---|---|---|
| **ق‑١** | **جبهة واحدة** — مهمّة واحدة قيد التنفيذ | `npm run plan` يرفض الثانية |
| **ق‑٢** | **لا إغلاق بلا بيّنة** — كوميت + اختبار حارس على القرص | `npm run plan` يرفض `done` العارية |
| **ق‑٣** | **كلّ ترحيل يبدأ محايدًا** — الأصناف كلّها `sale`، والوحدات بمعامل ١، والقوائم اختيارية | اختبار **لقطة ذهبية**: تُلتقط الأرصدة والتقارير قبل الترحيل، ويُثبَت تطابقها بعده. «لا يتغيّر رقم واحد» جملةٌ تُختبَر لا تُقال |
| **ق‑٤** | **لا سياسة مخبوزة** — القرارات ٤–٧ من `settings/current` | التراجع يصير **تغيير إعداد** لا إرجاع كوميت ولا نشرًا جديدًا |
| **ق‑٥** | **الحقيقة على الخادم** — حارس الواجهة وحده ليس حارسًا | كلّ منعٍ في `firestore.rules` أيضًا، ويُختبَر بالمحاكي |
| **ق‑٦** | **فرع لكلّ مرحلة** + البوّابة الخضراء قبل كلّ كوميت نهائيّ | `build` + `test` + `audit` + `plan` |
| **ق‑٧** | **لا مسّ لنطاق وكيلٍ آخر** غير مرفوع | مدخل موسوم `[Claude]`/`[Codex]` في التسليم |
| **ق‑٨** | **تحقّق قبل الثقة** — راجع الكود قبل الجزم بأيّ حالة | فجوات المتتبّع تحمل حقل `verified` بتاريخ الفحص ومصدره |
| **ق‑٩** | **المهمّة التي كبرت تُقسَّم قبل التوقّف** — لا تُترك نصفًا بلا تفكيك | مهامّ فرعية جديدة في المتتبّع، لا في الذاكرة |
| **ق‑١٠** | **ما يمسّ سلوك المستخدم يسبقه إبلاغ** (نزاهة التاريخ نموذجًا) | مهمّة مستقلّة على المالك في المتتبّع (`م٢-د`) |

**قاعدة التراجع:** أيّ مرحلة يجب أن تكون قابلة للإيقاف بإعدادٍ أو بإرجاع فرعٍ واحد، بلا فقدان بيانات أُدخلت في أثنائها. إن لم تكن كذلك — فُكّكها حتّى تصير.

## ٦ — الحدود

- الحارس يفحص **اتّساق المتتبّع**، لا صحّة الشيفرة. صحّة الشيفرة مسؤوليّة `npm test` و`npm run audit`.
- الحارس لا يمنع كتابة `done` كذبًا ببيّنة ملفّقة — يمنع الإغلاق **بلا** بيّنة. الصدق يبقى شرطًا بشريًّا.
- المتتبّع لا يُغني عن `ROADMAP.md`؛ ذاك للخطة الأمّ، وهذا للمرحلة الأولى وحدها.
