# قاعدة البيانات — PostgreSQL على جهازك

> **الحال اليوم:** القاعدةُ تعمل ومرآةُ البيانات حيّة. **والبوّابةُ ما زالت تقرأ من Firebase** — لم يتغيّر شيءٌ عند الموظّفين. التحويلُ خطوةٌ قادمةٌ بأمر المالك وحدَه.

## لماذا

في 2026-09-05 نفدت حصّةُ القراءة المجّانيّة من Firestore (٦١ ألف قراءة مقابل ٣٦ كتابة) فتوقّفت البوّابةُ ساعاتٍ، والجردُ في الغد. عُولج الطارئ، لكنّ الدرسَ ثبت: **الاعتمادُ على حصّةٍ لا نملكها خطرٌ تشغيليّ لا مسألةُ كلفة**.

والهدفُ الأصليّ أقدم: إخراجُ البيانات إلى سيرفرٍ داخل الشركة، ببنيةٍ لا ترتبط بمزوّدٍ بعينه. ولهذا **PostgreSQL قياسيٌّ بحت** — ما يعمل هنا يعمل حرفيًّا على سيرفر الشركة، ولا يتغيّر إلّا `DATABASE_URL`.

## التشغيل السريع

```bash
docker compose -f db/docker-compose.yml up -d
```

القاعدةُ على المنفذ **5433** (لا 5432 — فذاك مشغولٌ بقاعدة أودو). ومخزنُها `warehouse-db-data` منفصلٌ تمامًا، فيستحيل أن يمسّ بيانات أودو.

| الأمر | الغرض |
|---|---|
| `npm run proof` | **بيّناتُ القاعدة — ٤٩ فحصًا** (يعدّها ولا يكتفي بغياب الخطأ) |
| `node scripts/reconcile.mjs` | مطابقةُ Firestore ⇄ PostgreSQL صفًّا صفًّا |
| `node db/sync/sync.mjs --plan` | يطبع خطّةَ المزامنة وكلفتَها **بلا اتّصالٍ بشيء** |
| `node db/sync/sync.mjs --once` | دورةُ مزامنةٍ واحدة |
| `node scripts/pg-import.mjs` | يولّد SQL من نسخةٍ مصدَّرة (لا يتّصل) |

    007-sync-rejects   الصفوفُ التي رفضتها القيود — دَينٌ معلوم
  sync/                حاويةُ المزامنة

## المزامنة — وكلفتُها مقيسةٌ قبل أن تُبنى

تقرأ من Firestore وتكتب هنا. **تُطفأ بعد التحويل.**

### ★★★ الرقمُ الذي قلب التصميم

الخطّةُ الأولى قالت «كلَّ دقيقتين». والقياس:

| التصميم | القراءاتُ يوميًّا |
|---|---|
| وتيرةٌ موحّدةٌ كلَّ دقيقتين | **٤٥٨٬٦٤٠** — تسعةُ أضعاف الحصّة |
| الحصّةُ المجّانيّة | ٥٠٬٠٠٠ |
| **الوتيرةُ المُدرَّجة (المعتمَدة)** | **١٦٥٦** — ٣٫٣٪ |

السبب: المجموعةُ الفرعيّةُ تُقرأ **أبًا أبًا**، ومجموعاتُ `documents` الثلاثُ وحدَها ٥٢٥ استعلامًا في الدورة. والعلاجُ وتيرةٌ بثلاث طبقات (٢ · ١٥ · ٦٠ دقيقة) تُشتقّ من الحجم المقيس.

> والرقمُ **مثبَّتٌ في اختبار** (`watermark.test.js`) كي لا يعود أحدٌ إلى الوتيرة الموحّدة صامتًا.

### ★★★ ختمُ الإنشاء ليس ختمَ تعديل

ستّةُ مساراتٍ تحمل `createdAt` وحدَه. ولو اتُّخذ علامةً مائيّةً — وشكلُه يغري — لصار الحكمُ «اقرأ ما أُنشئ بعد كذا»، **فمستندٌ أُنشئ أمسِ وعُدّل اليومَ لا يُقرأ أبدًا**. لا خطأَ يُرفع ولا سطرَ يُسجَّل.

⇒ فالتغطيةُ الكاملةُ شرط، والمسحُ الكاملُ هو البديل. وختمُ الإنشاء يصلح **للمجموعة الملحقة-فقط وحدَها** — وذلك مُعلَنٌ في `firestore.rules` بـ`allow update, delete: if false`، فيُشتقّ اشتقاقًا لا يُكتب قائمةً تتقادم.

### ★★★ وصفٌّ فاسدٌ لا يُسقط الدفعة

أوّلُ تشغيلٍ حيٍّ كشفه: باركودٌ واحدٌ مكرَّرٌ رفضته القاعدة **فبقيت ١١٩٨ صنفًا خارج المرآة**، والمحاولةُ تتكرّر كلَّ دقيقتين بنفس الفشل.

العلاجُ ثلاثيّ:
1. الدفعةُ **تُنصَّف** عند الفشل حتّى يُعزل الفاسد — الكلفةُ بعدد الفاسد لا عدد الصفوف.
2. المرفوضُ يُسجَّل في **`sync_rejects`** بمعرّفه وسببه.
3. والعلامةُ **تتقدّم رغم الرفض** — ولولا الجدول لكان فقدًا صامتًا؛ ومعه دَينٌ يُقرأ باستعلامٍ واحد.

```sql
SELECT * FROM sync_rejects;   -- الجدولُ الفارغُ = صفرُ دَين
SELECT * FROM sync_cost_daily; -- كم كلّفتنا المزامنةُ اليوم
```

## الخادم — PostgREST وجسرُ الرمز

```bash
docker compose -f db/docker-compose.yml --profile api up -d --build
```

خدمتان على الجهاز وحدَه (`127.0.0.1` — والوصولُ من الخارج بالنفق لا بمنفذٍ مكشوف):

| | |
|---|---|
| **`postgrest`** :3000 | يفتح الجداولَ عبر HTTP **محكومةً بـRLS**. يتّصل بدور `authenticator` الذي **لا يقرأ جدولًا واحدًا** — كلُّ ما يملكه أن يتقمّص `web_anon` أو `web_user`، فتسريبُ كلمته وحدَها لا يكشف صفًّا |
| **`auth`** :3001 | جسرُ الرمز — `POST /token` بترويسة `Authorization: Bearer <رمز Firebase>` ⟵ رمزُ قاعدةٍ يحمل الدور |

### ★★★ ولماذا جسرٌ أصلًا؟ القياسُ فرضه ولم يتركه اختيارًا

قِيس رمزُ Firebase الحقيقيّ: `RS256` · `kid` **متبدّل** · صلاحيّةُ ساعة · **وبلا أيّ دعوى مخصّصة**. ومرجعُ PostgREST ينصّ: «إن أرسل العميلُ رمزًا **بلا دعوى `role`** ينتقل إلى الدور المجهول».

⇒ فرمزُ Firebase الخام يجعل كلَّ طلبٍ يعمل بدور `web_anon` فيرى **صفرَ صفوف — بلا خطأٍ ولا تحذير**. عطبٌ صامتٌ تامّ: النظامُ «يعمل» ويُرجع لا شيء.

وحقنُ الدور في رمز Firebase يحتاج **مفتاحَ حسابِ خدمة** تمنعه الخطّة. وPostgREST **لا يجلب مفاتيحَ Google ولا يجدّدها**، فالثابتُ يتقادم ويُقفل الجميع.

**والجسرُ يحلّ الثلاثةَ معًا**: يتحقّق بمفاتيح Google الحيّة (مخزَّنةً بمهلتها المعلَنة ≈ ٥ ساعات، وتُجدَّد عند أوّل مفتاحٍ مجهول)، ويُصدر رمزًا يحمل `role`. **وبلا تبعيّةٍ واحدة** — `node:crypto` و`fetch` المدمجان.

★★ **ولا يعيش الرمزُ الصادرُ أطولَ من رمز Firebase أبدًا** (أقلُّ المدّتين، بسقف ٣٠ دقيقة). ولولا هذا لبقي رمزُ قاعدةٍ صالحًا بعد إقفال الحساب — بابٌ خلفيٌّ يعيش نصفَ ساعةٍ بعد الإغلاق.

### البيّنةُ الحيّة (2026-09-10)

| الفحص | النتيجة |
|---|---|
| بلا رمز | **401 — permission denied** |
| عبر الجسر | ٢٠٠ · `role=web_user` |
| قراءةُ الأصناف/المستندات/المستخدمين | ٢٠٠ · **١٧ مستخدمًا** |
| توقيعٌ مزوَّر | **401** |
| **ترقيةُ الدور إلى `postgres`** | **401** |

و١٣ اختبارَ وحدةٍ في `db/auth/verify.test.js` — تُولّد مفتاحَ RSA حقيقيًّا وتوقّع به، فتجرّب **رمزَ مهاجمٍ** و**رمزًا من مشروعٍ آخر** و`alg: none` **وترقيةَ الدور بالتزوير**.

## صلاحيّةُ القراءة (RLS)

٩٨ قاعدةَ قراءةٍ في `firestore.rules` **تنطوي في تسعِ سياساتٍ لا غير** — و٨٨ منها `signedIn()` وحدَها.

والصلاحيّةُ **في القاعدة نفسها** لا في خادمٍ يُكتب يدًا: لا يتجاوزها مسارٌ نُسي، ولا سكربتٌ لم نكتبه، ولا `psql` مباشرةً.

⚠️ **وملاحظةٌ نُقلت كما هي ولم تُصلَح:** القواعدُ الحاليّة **لا تشترط أن يكون الحسابُ مفعَّلًا للقراءة**، فموظّفٌ أُوقف حسابُه يقرأ ما دام رمزُه صالحًا. تشديدُها قرارُ المالك لا انزلاقٌ داخل هجرة — وهو سطرٌ واحد (`AND is_active()`).

## قواعدُ تُلزم من يعمل هنا

| | |
|---|---|
| **ملفّاتُ `schema/` تُنفَّذ مرّةً عند أوّل إنشاء** | فما يُغيَّر يُغيَّر **بترحيلٍ جديدٍ مرقّم**، لا بتعديل ملفٍّ سابق |
| **لا جدولَ بلا RLS** | يفحصه `006` ويُسقط الترحيل. والخطرُ ليس سياسةً خاطئةً بل **جدولًا مفتوحًا بلا خطأٍ ولا تحذير** |
| **البيّنةُ تُعاد بلا أثر** | كلُّ ملفٍّ في `test/` ينتهي بـ`ROLLBACK` — يُشغَّل على قاعدةٍ فيها بياناتٌ حقيقيّة |
| **والبيّنةُ تُعَدُّ لا تُقرأ** | `npm run proof` يقارن عددَ الفحوص بحدٍّ أدنى معلَن. والسببُ درسٌ وقع: `proof.sql` أعلن ٢٤ فحصًا وكان **يُطلق ٦** — يموت في منتصفه ولا يطبع «تُخطّيت» |
| **لا تبعيّةَ جديدة** | لا سائقَ `pg`: يُولَّد SQL ويُمرَّر إلى `psql` |

### أسرارٌ لا تدخل git

`db/.env` و`db/dump/` و`db/secrets/` **مُتجاهَلةٌ كلُّها**. انسخ `db/.env.example` واملأ سطرين.

⚠️ **ومزلقُ ويندوز:** `Set-Content -Encoding utf8` في PowerShell 5.1 يكتب **BOM ونهاياتِ أسطرٍ ويندوزيّة**، فيدخل حرفٌ خفيٌّ في آخر كلمة المرور **وتفشل المصادقةُ برسالةٍ مضلّلة**. طبِّع الملفَّ إن حدث:

```bash
sed -i '1s/^\xEF\xBB\xBF//' db/.env && sed -i 's/\r$//' db/.env
```
